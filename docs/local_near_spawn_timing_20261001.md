# PC 연속보스 젠 안내 타이밍 수정

## 원인

2026-10-01 로그의 라타토스크~파르바 6마리는 약 42초에 걸친
`SPAWN_CONFIRMED_NEAR_SEQUENCE`였다. Discord 전용 예약 정보는 있었으나,
로컬 출력은 일반 연속 파일 재생으로 빠져 보스 사이의 대기 시간이 사라졌다.
로그만으로 실제 스피커 출력 시각까지 측정한 것은 아니다.

## 변경

- 요청에 보스별 정확한 젠 시각과 음성 파일을 유지한다.
- PC와 Discord가 같은 개별 클립 타임라인을 사용한다. 차임벨은 처음 한 번만 재생한다.
- 보스 이름은 음성 길이만큼 앞에서 시작하고 마지막 `젠` 클립을 해당 젠 시각에 맞춘다.
- TTS도 이름과 `젠`을 분리한다. 예약 음성이 없을 때 전체 문장을 조기에 재생하지 않는다.
- PC 연속보스 전용 `__PLAYNOW__` 명령은 앞 음성의 종료 대기 때문에 다음 예약 명령이 밀리지 않게 한다.
  기존 일반 재생 명령은 유지한다.
- 전체 타임라인 종료까지 음성 통로를 예약하고, 중지·세대 변경·인계 차단 시 남은 예약을 취소한다.
- 음성 테스트 로그가 켜진 경우 클립별 예정 시각, 명령 전송 시각, 지연을 기록한다.
  전송 시각은 스피커에서 실제 소리가 시작된 시각과는 구분한다.

## 검증

`python -m unittest test_near_spawn_timeline test_audio_pipeline test_voice_bridge_receipts -q`

가상 시계와 모의 출력으로 20개 통과. 당시 6마리의 소수점 젠 시각, 차임벨 횟수,
TTS, 취소, 음성 부재, Discord 예약 길이, 기존 일반 재생 명령 유지를 확인했다.
실제 음성 송출·프로그램 실행·설정 변경·배포 빌드는 하지 않았다.
실제 Windows 오디오 장치 지연은 사용자 재생 테스트로 확인해야 한다.
