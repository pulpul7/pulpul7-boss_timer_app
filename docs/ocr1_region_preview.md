# OCR1 영역 표시

스케줄 입력을 열면 별도의 비모달 확인창과 게임 위 테두리가 표시된다.
1600×900 오딘 클라이언트에서만 표시하며 창 이동 시 위치를 따라간다.
확인창은 스샷찍기 팝업 오른쪽에 6픽셀 간격으로 붙고 팝업 이동/재열기를 따라간다.
게임을 못 찾거나 크기가 다르면 안내만 표시하고 캡처나 OCR은 실행하지 않는다.

- 전체 화면/고정 보드 테두리는 표시하지 않는다. OCR1은 해당 넓은 범위의 글자도 읽지 않는다.
- 초록: 현재시간 글자를 고르는 기본 검색 범위.
- 파랑/노랑: 보스이름/남은시간 기본 영역. 기존 판정은 글자 겹침과 영역 바깥 여백도 허용한다.
- `재시도 영역`: 재시도에서도 같은 글자 영역만 허용함을 표시한다.
  확대 crop 내부라도 허용 영역 밖 픽셀은 검정색이므로 주변 글자는 다시 읽지 않는다.

챕터는 확인창에서 수동 선택한다. 선택은 미리보기에만 사용하고 실제 OCR 판정을 바꾸지 않는다.
별도 초기 OCR을 실행하거나 스크린샷을 저장하지 않는다.
실제 OCR1은 내부의 과거 이름 `_build_schedule_input_ocr2_result_for_item` 경로를 사용하므로,
그 경로의 고정 보드/슬롯/crop 계산 함수를 직접 재사용한다. 정밀 추적용 작은 ROI와 별개이다.

최초 챕터가 미확정이므로 3칸/4칸 레이아웃의 이름·시간 후보 영역 합집합과 현재시간만 남긴다.
합집합을 큰 사각형 하나로 확장하지 않는다. 원래 좌표가 유지되는 1600×900 메모리 비트맵에서
나머지를 검정색 처리한 뒤 Windows OCR에 넘긴다. 원본 스샷은 변경하거나 덮어쓰지 않는다.
지역 판독에는 남겨진 보스 글자를 사용하므로, 가림이 실제 보스 글자를 덮으면 여전히 인식 실패가 가능하다.

F2/스샷찍기/초단위 찍기 직전에 표시창과 테두리를 숨긴다.
촬영·변환 종료 후 다시 표시하고, 스케줄 입력창을 닫으면 타이머와 테두리도 정리한다.
Windows 캡처 제외 속성과 클릭 통과 속성도 테두리에 적용하며, 캡처 제외 설정 실패 시 테두리를 띄우지 않는다.
확인창의 X로 끄거나 `영역 표시`를 해제할 수 있다. 입력창을 다시 열면 다시 표시한다.

OCR2는 별도 실행 경로지만 Windows OCR 호출과 일부 함수는 공유한다.
픽셀 제한 인자는 OCR1에서만 지정하며 OCR2의 기존 입력·재시도 동작은 유지한다.
위쪽 줄 보스 시간 영역 하단 +4픽셀은 OCR1 고정 경로에만 적용한다. 아래쪽 시간 영역은 그대로다.
OCR1 이름 영역은 누적 기준 위쪽 줄 상단 +12픽셀, 아래쪽 줄 상단 +4픽셀, 전체 우측 -12픽셀로 축소한다.
전체 보스 시간 영역은 좌측 +10픽셀로 축소한다. 위쪽 시간 하단 +4픽셀은 유지한다.
이름 영역 좌측/하단과 OCR2는 변경하지 않는다. 판독 마스크와 미리보기는 같은 슬롯 좌표를 사용한다.
현재시간은 초단위 찍기의 `precision_capture_layout.GAME_CLOCK_BOUNDS`를 직접 참조한다.
현재 좌표는 (190,256)~(420,306), 230×50픽셀이다. OCR1 픽셀 마스크·미리보기·시간 글자 선택·
집중 재시도가 모두 같은 좌표를 사용한다. 실패해도 화면 전체로 검색 범위를 넓히지 않는다.
OCR2의 기존 현재시간 선택·재시도 좌표와 정밀 추적 자체는 변경하지 않는다.
비빌드 좌표/수명주기 테스트를 사용하며 실제 게임 화면에서의 가시성은 별도 확인이 필요하다.
