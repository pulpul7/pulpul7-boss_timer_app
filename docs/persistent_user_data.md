# 버전 간 사용자 데이터 유지

동일 Windows 사용자에서는 `%APPDATA%/BossTimer`가 공통 저장 위치다.
실행 파일과 배포 리소스 위치는 바꾸지 않는다.

| 데이터 | 위치 |
| --- | --- |
| 환경설정 / 현재 시즌 | `boss_timer_settings.ini` |
| 담당자 이름·고유 ID | `administrator_identity.json` (시즌과 분리, 배포 제외) |
| 시즌·길드·서버 이력 | `season_history.json`, `active_server_profile.json` |
| 시즌/서버별 스케줄·보스·알람·롤백·Discord 설정 | 기존 `server_profiles/<season>/<server>/` 유지 |
| 서버 미선택 상태의 스케줄·알람 | `schedule_state.json`, `schedule_alarm_settings.json` |
| 공통 기본설정 | `init/` |
| 통계·시즌 기록 | `boss_capture_records/`, `archive_logs/`, `season_prestart_logs/` |
| 로컬 공유 스케줄·다운로드 캐시 | `shared_schedules/`, `cache/github_data/` |
| 알리미 설정·수집·송출 이력 | `notice_data/` |
| 알리미 모듈 설치·업데이트 이력 | `update_ai/` |

## 최초 이관

- 시작 시 서버/시즌 선택과 기본값 로딩 **이전**에 실행 폴더의 구형 데이터를 복사한다.
- 기존 AppData 파일은 빈 파일도 덮어쓰지 않는다. 기존 서버별 스케줄은 이관 대상이 아니다.
- 원본은 삭제하지 않는다. 완료 표식 `portable_data_migration_v1.json` 후에는 구형 파일을 다시 복사하지 않는다.
- 복사 오류 시 성공 표식을 남기지 않고 시작을 중단한다. 다음 실행에서 누락분만 이어서 복사한다.
- 버전이 달라졌다는 이유로 INI/알람/기본값을 삭제하는 이전 코드는 비활성화했다.
- 새 설정 저장은 임시 파일 + 교체로 기록하여 중간 종료로 빈 INI가 남는 위험을 줄였다.

이번 PC는 현재 파일을 AppData로 복사하고 현재 차임벨/환경설정을 기본값·롤백에 반영했다.
변경 전 기본값/롤백: `settings_seed_backups/environment_20260928_161937_498250/`.

**기존 배포 사용자:** 최초 한 번은 새 실행 파일을 기존 사용 폴더에서 실행해야 실행 폴더에만
있던 길드·시즌 정보를 이관할 수 있다. 이관 후부터 다른 폴더의 새 버전도 자동으로 이어받는다.
아직 이관하지 않은 구형 프로그램 폴더를 프로그램이 임의로 검색하거나 합치지는 않는다.

수정 전 프로그램이 켜져 있다면 설정을 더 변경하기 전에 종료하고 수정본을 실행한다.
구형 프로그램은 계속 옛 경로에 저장하므로 수정본과 번갈아 쓰거나 동시에 실행하지 않는다.
다른 PC/Windows 계정은 별도 AppData이므로 자동으로 계정 간 복사되지 않는다.

## 새 시즌의 시작 스케줄

- 새 버전 실행은 현재 AppData 시즌/서버 프로필을 그대로 읽는다. 새 시즌 생성과 구분한다.
- 명시적인 새 시즌 설정 시, 현재 메모리 스케줄을 새 프로필의 `schedule_state.json`으로 복사한다.
- 복사는 프로필 활성화 전 준비 단계에서 수행하며 소수점 포함 절대시간을 이동·반올림하지 않는다.
- 이전 시즌 파일은 보존한다. 일반 서버 선택에는 이 복사 경로를 사용하지 않는다.
- 새 시즌에 스케줄 파일이 이미 있으면 빈 파일도 덮어쓰지 않는다.
- 출처는 `season_copy`로 바꾸고 새 서버/시즌 정보를 사용한다. 이전 GitHub 버전과
  이전 시즌을 되살릴 수 있는 컷 되돌리기 이력은 복사본에서 제외한다.
- 새 시즌 설정창이 닫힌 뒤 스케줄을 다시 초기화하던 처리는 제거했다.
  같은 시즌 재시작도 스케줄은 보존하고 시작 시점만 바꾼다.
- 이미 초기화되어 저장된 시즌은 임의로 덮어쓰지 않는다. 기존 수동 동기화/복구를 이용한다.

2026-10-01 추가: 이미 존재하는 다른 시즌 프로필을 선택하면 현재/대상 스케줄 건수와
차임벨 선택을 자체 중앙 팝업으로 확인한다. 기본 선택은 `아니요`이며, 취소하면 시즌·담당자·
Discord 연결을 변경하지 않는다. 기존 빈 시즌도 예외 없이 확인하고 자동 덮어쓰기하지 않는다.
사용하지 않은 낮은 시즌 번호로 변경할 때도 현재 활성 같은 서버의 설정을 이어받는다.
복사 전 현재 알람/차임벨 설정 저장에 실패하면 시즌 변경을 중단한다.

## 시즌 생성·관리·이어하기 (2026-10-01)

- 새 시즌 시작 시 `archive_logs/<시즌명>/`와 `server_profiles/season_<번호>/`를 즉시 생성한다.
  스케줄이 비어 있어도 새 서버 프로필에 `schedule_state.json`을 만든다.
- 시즌 설정 폴더의 `season_info.json`에 시작일·서버·길드·시작에 사용한 서버 프로필과
  기록 폴더 이름을 보관한다. 기존 `season_history.json`과 서버별 스케줄/설정 경로는 유지한다.
- 시즌 시작창에서 새 번호는 `시작`, 저장된 다른 번호는 `이어하기`로 구분한다.
  기본 새 번호는 저장된 번호 중 가장 큰 번호 다음으로 잡는다. 사용하지 않은 번호를 직접 입력할 수도 있다.
- 이어하기는 기존 시작일·서버·길드·스케줄·차임벨·설정을 불러온다. 현재 시즌의 자료는 먼저 저장하고,
  대상 시즌의 스케줄이나 Discord 설정을 현재 시즌 자료로 덮어쓰지 않는다.
  현재 시즌 번호를 입력한 경우의 시작일 변경은 기존 확인 절차를 유지한다.
- 새 시즌 시작과 이어하기 모두 프로필 활성화·선택 파일·시즌 이력·현재 설정 저장이 완료된 뒤
  성공으로 처리한다. 실패하면 이전 시즌 번호·프로필·스케줄·차임벨·삭제 이력을 복원하고
  이전 선택 파일과 시즌 이력도 다시 저장한다. 되돌린 상태의 저장까지 실패하면 별도로 안내한다.
- 시작창의 `시즌관리` 또는 기록로그의 `보관관리`에서 시즌을 조회·이어하기·삭제할 수 있다.
  기록 폴더가 없어도 설정 폴더나 시즌 이력이 있으면 목록에 표시하며, 자동으로 이력을 지우지 않는다.
  구형 시즌의 시작일 정보가 없으면 `수정`에서 시작일을 입력한 뒤 이어한다.
- 시즌 전체 삭제는 시즌명 직접 입력 후 선택 시즌의 모든 서버 스케줄·설정·롤백,
  보관 기록·시작일 이전 기록과 시즌 이력을 제거한다. 현재/사용 중인 프로필의 시즌은 삭제할 수 없다.
  이름 변경 전 기록 폴더도 같은 시즌의 폴더 이력으로 관리한다.
- 보관 정리 기능은 기존처럼 오래된 기록 폴더만 정리한다. 공용 기본값·음성 파일·
  담당자 ID·별도 기록표 파일은 시즌 전체 삭제 대상에 포함하지 않는다.
- 이번 변경은 소스와 문서만 반영했다. 실제 시즌 생성·전환·삭제, 테스트, 빌드는 실행하지 않았다.

2026-10-01 삭제 접근 거부 보완: 구형 시즌의 `settings_rollback/baseline` 등에서
폴더 권한이 제한되어 있으면 삭제 전에 선택 시즌 내부의 해당 항목만 부모 권한으로 재설정한다.
재설정은 경로별로 수행하며 다른 시즌·공용 폴더나 링크를 따라가지 않는다.
읽기 전용 항목은 삭제 실패 시 해당 항목의 읽기 전용 속성을 해제하고 재시도한다.
권한 복구가 불가능하면 중앙 팝업에 실패 경로와 관리자 권한으로 다시 실행하는 방법을 표시한다.
폴더 사전 접근 검사에 실패하면 파일 삭제를 시작하지 않고, 삭제 실패 시 시즌 이력은 유지한다.
실제 사용자 폴더의 권한 변경이나 삭제는 수행하지 않았다.

## 차임벨

- 현재 선택: 일반 `안내방송_비행기1.wav`, 고정 `안내방송_비행기3.wav`, 연속 `안내방송_비행기2.wav`.
- 배포/롤백에는 `wave/...` 상대 경로로 보관한다.
- 구형 절대 경로의 `wave` 파일도 현재 실행/리소스 폴더에서 찾는다.
- 파일이 없는 경우 선택 경로는 유지하고 재생할 때만 존재 여부를 확인한다.
- 사용자가 명시적으로 비운 선택은 그대로 유지한다. 모든 서버 설정을 강제로 바꾸지 않는다.

## 남겨 둔 파일

`wave`, `voice`, `user_voice`, 배경 이미지와 `tts_캐쉬`는 기존 배포/사용자 파일 경로를 유지한다.
직접 추가한 음성·이미지는 새 폴더에 별도로 복사해야 한다. 외부 경로 음성은 파일도 유지해야 한다.
기존 토큰·TTS 설정은 원래 AppData에 있던 위치를 사용하며 배포 기본값에는 개인 정보를 포함하지 않는다.

실제 GUI/Discord 송출과 EXE 빌드는 수행하지 않았다. 단위 테스트는 임시 데이터로 경로 이관,
기존 파일 보존, 복사 실패/경쟁, 버전 변경, 차임벨 경로 유지를 검증한다.
