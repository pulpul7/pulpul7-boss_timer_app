# PC 네트워크 점검 — 2026-10-07

공유기·PC 설정을 변경하지 않고 조회와 소량의 통신 검사만 진행했습니다.
검사는 20:29 음성 재접속 이후에 수행했으므로 과거 장애 순간의 상태를 증명하지 않습니다.

## 측정 결과

유선 Realtek PCIe GbE Family Controller, 링크 1Gbps.
세 대상에 동시에 1초 간격으로 각각 60회 ICMP 요청을 보냈습니다.

| 대상 | 성공/시도 | 손실 | 최소/평균/최대 왕복 시간 |
| --- | --- | --- | --- |
| 공유기 192.168.0.1 | 60/60 | 0% | 0 / 0.33 / 7ms |
| Cloudflare 1.1.1.1 | 60/60 | 0% | 11 / 11.82 / 30ms |
| Google 8.8.8.8 | 60/60 | 0% | 31 / 32.45 / 50ms |

측정 중 랜카드 수신·송신 오류 및 폐기 카운터 증가 없음.
누적 수신 폐기는 검사 전 100이었으며 증가하지 않아 이번 단절과 연관 지을 수 없습니다.

Discord DNS 조회: discord.com 313ms, gateway.discord.gg 44ms, 모두 성공.
각 대상의 TCP 443 + TLS 1.3 접속을 3회씩 검사해 6/6 성공했습니다.
discord.com은 23~57ms, gateway.discord.gg는 23~70ms였습니다.
이는 짧은 접속 확인이며 장시간 WebSocket 유지나 실제 Discord 음성 UDP 경로 검사가 아닙니다.

기본 IPv4 경로는 유선 인터페이스 한 개. 활성 VPN/가상 어댑터는 조회 결과 없었습니다.
WinHTTP 프록시 없음, 사용자 프록시 꺼짐, 자동 설정 스크립트 없음.
최근 3시간 System 로그 조회에서 지정한 네트워크·전원 관련 제공자의 사건은 발견하지 못했습니다.
조회한 항목에 기록이 없다는 뜻이며 모든 장애 가능성을 제외하지 않습니다.
경로 추적은 첫 번째 공유기 다음에 통신사 주소로 진행했습니다.
중간 홉 일부의 ICMP 무응답은 목적지 핑 손실을 의미하지 않습니다.

## 비교 점검 후보

현재 랜카드 설정:

- 에너지 효율적인 이더넷(EEE): 사용
- 절전형 이더넷(Green Ethernet): 사용
- Power Saving Mode: 사용
- 컴퓨터가 이 장치를 끌 수 있음: Enabled
- Advanced EEE / Gigabit 자동 비활성화: 사용 안 함
- 속도 및 이중: 자동 교섭
- 드라이버: 10.76.50.2025, 2025-05-14

절전 옵션은 원인으로 확정되지 않았습니다. 필요하면 옵션을 기록하고 하나씩 꺼서 비교합니다.
실제 Realtek 드라이버 변경은 PC/메인보드 제조사 제공 버전과 비교해야 합니다.

사용자는 공유기가 ipTIME AX1500SR이고 현재 브릿지 모드를 사용하지 않는다고 확인했습니다.
설정 마법사 대신 관리도구에서 QoS·사용 제한·펌웨어 버전·시스템 로그를 조회합니다.
20:29:19 전후 WAN 연결 해제·재연결·주소 재할당·공유기 재시작 기록이 있는지 우선 확인합니다.
QoS는 기존 사용 여부와 제한 규칙부터 확인하며, 꺼져 있다면 그대로 둡니다.

참고: [ipTIME QoS 설정](https://www.iptime.com/support/faq/25973),
[ipTIME 인터넷 사용 제한](https://www.iptime.com/support/faq/25985).
다른 제조사인 [Intel의 절전 옵션 점검 안내](https://www.intel.com/content/www/us/en/support/articles/000059067/ethernet-products/gigabit-ethernet-controllers-up-to-2-5gbe.html)는
절전 설정을 비교할 근거일 뿐, 이 PC의 Realtek에 같은 결함이 있다는 증거가 아닙니다.

Discord 앱의 음성 설정은 별도 Python 봇에 직접 적용되지 않습니다.
공유기 설정과 PC 어댑터 상태, 봇의 연결 로그를 기준으로 판단합니다.
