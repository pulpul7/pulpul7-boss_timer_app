## 확인된 원인

확인 시점의 HEAD `3696d81`에는 프로그램 태그 `v5.5.5`가 있습니다. 그런데 `boss_timer_gui.spec`의 빌드 번호와 GUI의 기본 번호는 `v5.5.1`에 고정되어 있고, 기존 `build_metadata.json`도 `v5.5.1` / `2026-10-03 16:06:38`입니다.

수정 전에는 소스 실행 시 Git의 가장 최근 생성 태그로 화면 번호를 덮어쓰는 반면, GUI 빌드는 고정 번호로 메타데이터를 생성했습니다. 따라서 소스 화면은 `v5.5.5`, 배포 EXE는 `v5.5.1`이 될 수 있는 불일치를 확인했습니다. 배포 폴더명이 `v5.5.5`라는 이유만으로 EXE의 내장 버전이 바뀌지는 않습니다. 이번에는 해당 배포 EXE 자체를 열어 내장 데이터를 대조하지 못했으므로 개별 배포 파일의 실제 내용까지 확정하지 않습니다.

또한 EXE를 Git 저장소 폴더에 두면 내장 번호·빌드 시각을 실행 폴더의 Git 정보로 덮어쓸 수 있었습니다. 전역 최신 태그 선택에는 다른 브랜치나 모듈의 태그가 섞일 가능성도 있습니다.

## 소스 수정

- `release_version.py`: 현재 소스에 연결된 가장 가까운 프로그램 태그를 선택합니다. `v숫자.숫자.숫자` 형식을 대상으로 하며 `fix`·`beta` 등의 접미사를 유지합니다. 일반적인 `tts-module-v…`·`notice-v…` 모듈 태그를 프로그램 번호로 사용하지 않습니다. Git이 없거나 조회에 실패하면 기존 기본 번호를 사용합니다.
- GUI 소스와 빌드 spec이 같은 선택 함수를 사용합니다. 현재 저장소에서 해석되는 번호는 `v5.5.5`입니다. 새 버전이나 태그를 임의로 생성하지 않았습니다.
- GUI 빌드 시 그 번호를 내장 메타데이터와 기본 알람 버전에 사용합니다. ZIP 이름은 완료된 GUI 빌드의 메타데이터에서 읽어 EXE와 맞춥니다.
- 배포 EXE는 내장 버전·빌드 시각을 그대로 표시하며 실행 폴더에서 Git을 조회하지 않습니다. 소스 실행의 추가 Git 조회는 기록되지 않은 진단 정보를 보충하는 데만 사용합니다.
- UTF-8 BOM이 붙은 메타데이터도 읽으며, 인코딩 오류가 있는 파일은 다음 후보로 넘어갑니다. 내장 메타데이터가 EXE 옆 파일보다 우선합니다.
- 오래된 빌드 인수인계 문서의 `v5.0.0` 안내를 현재 버전 선택 방식으로 교체했습니다.
