# 보스 사용 설정

## 출현 중 입력과 기존 예정 시간

같은 보스를 새로 `출현 중`으로 입력하면 기존 미래 예정 체인도 현재 입력의 덮어쓰기 범위에서 교체한다.
실제 출현 중일 때는 다음 출현 시각이 미확정이므로 예전 예정 시간과 동시에 남기지 않는다.
기본 범위에서는 과거 기록을 보존하며 다른 보스와 침공 일정은 구분한다. 덮어쓰기 확인에도 제거될 미래 행을 포함한다.
정기점검 설정으로 생성 기간을 늘릴 때도 현재 출현 중인 보스는 과거 기록에서 미래 일정을 다시 생성하지 않는다.
정확한 시간이나 컷을 새로 입력하면 기존 출현 중 상태를 교체하는 흐름을 따른다.
이미 저장된 충돌 자료를 로드만으로 일괄 삭제하거나 시간을 추정해 바꾸지는 않는다.
회귀 검증은 `test_schedule_active_import.py`이며 EXE·웹 정적 파일은 생성하지 않는다.

## 점검·서버오픈 입력

`정기점검`은 날짜별 정기점검 회차로, `임시점검`은 임시 회차로 구분한다. 공지에서 확인된 특정 주의 정기점검은 매주 반복 설정을 바꾸지 않는다.
`1031 서버오픈 컷`은 일반 보스가 아닌 서버오픈 제어로 처리하며 가장 가까운 지난 10:31을 기록한다.
`1일 1031 서버오픈 컷`은 하루 전 날짜 10:31이다. 날짜를 확인한 뒤 적용하며 `0일`은 항상 입력 당일을 뜻한다.
오픈은 대응하는 점검 한 건에 연결하고, 점검 전 일반 보스 자료를 다시 살리지 않는다. 과거 점검 기록은 자동 삭제하지 않는다.
기존 지난 임시점검 입력의 이력 전용 규칙은 유지한다. 상세 기준은 [점검 구조 문서](maintenance_structure_review.md)를 따른다.

## 보스별 사용 여부

보스 설정 목록에서 보스명 오른쪽의 `사용` 체크를 누르면 바로 저장됩니다.
오른쪽 추가/수정 폼의 `사용` 체크는 기존 적용/저장 흐름을 따릅니다.
기본값은 사용 ON이며 기존 8열 보스 정의 파일은 모두 ON으로 읽습니다.

사용 OFF는 삭제가 아닌 새 입력 제외입니다.

- OCR 1·2: 지역/카드 배치 판별과 전체 슬롯 번호는 유지하고 해당 보스의 시간 해석·재시도를 건너뜁니다.
- 캐시된 OCR 결과: 사용 OFF인 보스는 텍스트로 출력하지 않습니다. 직접 수정한 입력 텍스트는 덮어쓰지 않습니다.
- 새 스케줄 입력·추가·붙여넣기·Discord 자동 입력: 정식 이름·약칭·침공 이름을 같은 설정으로 제외합니다.
- 출현 중 추가 후보와 미입력 보스 안내에서도 제외합니다. OFF 보스의 중복 입력 때문에 경고하지 않습니다.
- 이미 등록된 스케줄/출현 중 목록/복구 자료는 삭제하거나 숨기지 않습니다. 기존 일정 수정·컷·조회·알람·복사도 유지합니다.

서버별 schedule_boss_definitions.txt의 마지막 9번째 열은 사용여부(1/0)입니다.
공동관리 boss_definitions 공유 JSON에도 enabled를 포함합니다. 구형 공유 JSON에 필드가 없으면
해당 PC의 기존 선택을 보존하고, 새 보스는 ON을 기본값으로 사용합니다.
이름 마이그레이션·약칭 중복 정리에서도 OFF를 보존합니다.
공유 설정의 내용 해시는 누락된 사용 필드와 명시적인 ON을 동일하게 처리해 구형 서버 자료와의
불필요한 내용 불일치를 피합니다. OFF는 반드시 다른 해시가 되며 원본 자료는 수정하지 않습니다.

입력 필터는 schedule_boss_usage.py로 분리했습니다. 일반 파싱/기존 일정 수정은 손실 없이 유지하고
새 입력 경로에서만 respect_boss_usage를 켭니다. Discord 봇 자체의 소스 변경은 없습니다.

진단 로그:

- schedule_boss_usage_changed: 보스와 새 사용 상태
- schedule_input_disabled_bosses_skipped: 새 입력에서 제외한 보스
- OCR scale_logs의 disabled_by_boss_settings: 원래 슬롯 번호와 제외한 보스

검증은 test_schedule_boss_usage.py의 입력/복구, OCR 좌표 보존, 캐시 필터,
미입력 안내, 저장 호환성, 공동관리 공유 및 체크 열 동작에 한정합니다.
실행 파일이나 배포 파일은 생성하지 않습니다. 적용/배포 시 GUI를 다시 빌드합니다.

## 입력창의 24시간 이내 자동 체크

입력창을 새로 열 때 현재 서버 오픈 날짜의 다음 날 00시부터 다음 정기·임시점검 직전까지는 24시간 이내 필터를 켭니다. 오픈 당일과 점검 이후에는 자동으로 체크하지 않습니다. 실제 공지에서 읽은 오픈 시각이나 유효한 수동 오픈 시각을 기존 입력 기준과 동일하게 사용합니다. 점검 중에는 지난 주 오픈을 이번 주 기준으로 오인하지 않도록 해당 오픈 이후 첫 점검 시각으로 기간을 제한합니다. 이미 열린 창에서 사용자가 바꾼 체크는 창을 다시 활성화하는 것만으로 덮어쓰지 않습니다. 이 자동 선택은 저장된 서버 스케줄을 변경하거나 입력을 확정하지 않습니다.

회귀 검증: `test_schedule_input_day_default.py` (오픈 당일·다음 날 자정·점검 경계·자정 이후 연장 오픈·임시점검·열린 창의 수동 조작 보존).
