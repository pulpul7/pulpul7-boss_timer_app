# Discord 보스 안내 메시지

- 제목은 `✦ 보탐매니저 안내 · BossTimer | 오늘 오후 6:47`처럼 표시한다.
  시간은 마지막 안내를 추가한 시각이며 영문 단계 푸터와 별도의 하단 시간은 표시하지 않는다.
- GUI의 음성 요청에 `notice_group_id`를 추가하여 기존 보스 이벤트/그룹 ID를 전달한다.
  녹음·캐시 TTS·초정밀 예약 재생에서 같은 ID를 사용하며 음성 재생 시점은 바꾸지 않는다.
- 채널·권한 세대·테스트 범위·종류·보스 ID·출현 시각을 함께 비교한다.
  동적 보스 ID에는 개별 보스의 정확한 출현 시각이 포함되어 있다. 구성원 ID를 정렬하여
  비교하며 음성 재생용 대표 시각은 비교에서 제외한다. 사전 안내가 첫 출현 시각을,
  근접 등장 안내가 마지막 출현 시각을 사용해도 같은 구성원의 박스에 누적한다.
  고정보스·점검처럼 ID에 시각이 없는 경우에는 전달된 목표 시각을 함께 비교한다.
  같은 보스의 다음 출현이나 다른 채널·권한 세대의 안내는 별도 메시지로 전송한다.
- 같은 출현의 다음 안내는 기존 Discord 메시지 본문의 한 ANSI 색상 코드 블록 안에 추가한다.
  단계 이름(5분 전·1분 전·등장 안내)과 개별 시각 줄 없이 실제 안내 내용만 세로로 누적한다.
  개별 코드 블록의 기본 여백을 없애기 위해 안내 사이에 빈 줄을 넣지 않는다.
  각 안내의 색상·리셋 코드는 유지한다. Discord 메시지에는 픽셀 단위 간격 설정이 없다.
  다른 보스의 안내가 사이에 들어와도 원래 메시지에 추가한다. 메시지는 원래 채팅 위치에 남는다.
- 메시지 갱신은 잠금으로 직렬화하되 음성 재생 큐와 별도 작업으로 수행한다.
  갱신 직전에 송출 권한을 재확인하여 늦게 끝난 이전 담당자의 작업을 차단한다.
- 순간적인 본문 표시 변화를 조사할 때 `discord_bot.log`의 `text_notice_sent`·
  `text_notice_updated`와 `text_notice_gateway_edit`의 메시지 ID·본문 해시를 비교한다.
  해시는 제목·본문·필드 텍스트만 비교하며 실제 색상 제어 문자는 로그에 쓰지 않는다.
  `text_channel_cleanup_deleted`에는 이전 메시지를 삭제한 시각이 기록된다.
  이 기록은 Discord 화면 깜빡임 자체를 감지하거나 해결하지 않는다.
- 완료되지 않은 안내는 묶음의 마지막 출현 시각 이후 15초까지 보관 개수 정리에서 보호한다.
  따라서 안내 진행 중에는 설정한 보관 개수보다 많은 메시지가 잠시 표시될 수 있다.
  완료한 메시지의 보관 우선순위는 작성 ID 대신 마지막 안내 시각으로 계산한다.
  사용자 글·고정 메시지·음성 패널은 기존과 같이 보존한다.
- 직접 삭제된 메시지는 다음 안내 때 새로 전송한다. Discord 본문 4,096자·전체 글자 수 한도에
  도달하면 다음 안내를 새 메시지에 이어서 전송한다.
- 메시지 참조는 봇 프로세스 메모리에 보관한다. Gateway 재접속 중에는 유지되지만
  봇 프로세스를 다시 실행하거나 담당자가 바뀌면 새 메시지에서 시작한다.
  구버전 GUI에는 ID가 없으므로 새 봇만 교체하면 누적 표시되지 않는다. GUI와 봇을 함께 교체한다.

실제 Discord 전송 테스트와 빌드는 사용자가 진행한다.
근거: [Discord 메시지 수정·Embed 제한](https://docs.discord.com/developers/resources/message).
