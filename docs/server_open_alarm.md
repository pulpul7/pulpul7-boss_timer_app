# 공지 기반 서버 오픈 알람

기존 공지 조회는 서버 오픈 시각을 스케줄 입력의 기준값으로만 제공했습니다.
점검/오픈 알람은 별도로 등록된 제어 항목만 읽어 자동 수집된 오픈 시각을 안내하지 못했습니다.

현재는 공지 기반 오픈 시각을 기존 점검 알람의 읽기 전용 대상에 함께 넣습니다.
게임 스케줄이나 서버 오픈 제어 항목을 새로 저장하지 않습니다.
스케줄 행의 표시/생성/삭제 규칙에도 영향을 주지 않습니다.

- 오픈 1분 전과 오픈 예정 시각에 각각 한 번 안내합니다.
- 기존 녹음 파일과 TTS 대체 경로, 로컬/Discord 음성 송출 처리를 사용합니다.
- 알람 틱을 잠깐 놓친 경우 최대 5초만 보완합니다. 과거 오픈 안내를 뒤늦게 반복하지 않습니다.
- 같은 날짜의 수동 서버 오픈 제어 항목이 있으면 수동 설정을 우선합니다.
- 정기점검 시작 전에는 다음 주 공지를 현재 오픈으로 사용하지 않습니다.
- 명확한 연장/완료 시각을 우선하고, 취소·충돌·불명확한 연장·본문 조회 오류가 있으면 추정하지 않습니다.
- 알리미의 자동 수집 또는 점검 카테고리를 끄면 신규 공지 기반 오픈 후보도 사용하지 않습니다.
- 기존 스케줄 입력의 오픈 기준은 종전처럼 점검 종료 이후에만 바뀝니다.

새 선택 API는 `get_server_open_alarm(server_id, now)`입니다.
알리미 모듈은 공지 파일의 변경 시각/크기를 비교하고 변경될 때만 JSON을 다시 읽습니다.
알람 확인 때문에 홈페이지 통신이나 별도 폴링을 추가하지 않습니다.
구형 외부 알리미 모듈에는 기존 `get_server_open_override`를 사용해 호환하며,
구형 모듈에서 1분 전 안내까지 사용하려면 새 모듈 소스를 함께 반영해야 합니다.

본체와 함께 제공되는 `notice_module` 소스를 수정했습니다. EXE/배포 ZIP은 생성하지 않았습니다.
순수 시간 선택과 GUI 메서드의 분리 검증을 수행했으며 실제 음성 송출은 사용자가 확인합니다.
