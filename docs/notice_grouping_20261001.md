# 참여 안내 문장과 기본값 정리 (2026-10-01)

## 안내 문장

- 다음 날 새벽, 점검 전 아침, 보스/길던 참여 독려에 같은 규칙을 적용한다.
- 기준 보스부터 **30분 미만**인 보스만 읽는다. 정확히 30분부터는 이 안내에서 제외한다.
- 첫 보스 기준으로 계산한다. 00:00, 00:20, 00:40이라면 앞의 두 보스만 포함한다.
- 한 번만 날짜·시간을 말한다. 두 보스는 이름을 모두, 세 보스부터는 `첫 이름 외 N개`로 안내한다.
- 예: `내일 새벽 0시 21분 최하층 강글, 최하층 굴베 일정이 있습니다. 많은 참여 부탁드립니다.`
- 저녁 독려의 기존 행사 우선순위는 유지한다. 공성전 등 선정된 대표 행사 이후의 30분 미만 구간을 사용한다.
- `{보스목록}`, `{참여안내}`뿐 아니라 저장돼 있는 `{시작시간}` + `{알림제목}` 문구에도 같은 보스 묶음을 적용한다.
- 원본 일정, 세부 시간, 알림 본문은 삭제하지 않는다. 개별 수동 편집 TTS는 기존 검토 절차를 유지한다.
- 변경된 자동 문장은 다음 스케줄 점검에서 다시 생성된다. 실제 음성 송출은 이번 검증에서 실행하지 않았다.

## 기록로그 관리

- 보관관리의 `선택 시즌 기록로그 관리`는 해당 AppData 시즌의 보스 목록/기록 수정·삭제 화면으로 연결한다.
- `기록표 기간 관리`는 AppData/boss_capture_records의 기존 기간 검색·삭제·보관 관리 창을 연다.
- 선택 폴더를 실제 보관 루트 안에서 검증한다. 기존 설치 폴더나 현재 시즌 폴더로 잘못 돌아가지 않게 조회 경로를 전달한다.
- 실제 사용자 기록 삭제는 하지 않았다. 회귀 검사는 임시 합성 자료만 사용했다.

현재 활성 프로필 `season_26 / 9`를 기준으로 29개 파일을 반영하고 바이트 비교로 확인했다.

- 공용 기본값: 프로젝트 init, AppData/init, 독립 알리미 모듈의 notice_defaults.json.
- 차임벨 선택: 일반 `wave/안내방송_비행기1.wav`, 고정 `wave/안내방송_비행기2.wav`, 연속 `wave/안내방송_비행기3.wav`.
