# 봇 수동 접속·대기 및 재접속 제한

## 명령

- `/보탐`: 기존 스케줄 조회 그대로 유지.
- `/보탐 동작:접속`: Discord 명령 입력창에서 `동작` 옵션의 `접속` 선택.
  호출자가 음성채널에 있으면 해당 채널, 없으면 설정의 기본 음성채널에 접속한다.
- `/초대`: 기존 명령은 같은 직접 연결 경로를 사용한다. 연결 직후 GUI에
  프로세스 재시작을 요청하던 동작은 제거했다.
- `/대기`: 해당 PC의 대기를 저장하고 음성 송출·자동 접속을 중단한다.
  진행 중 음성과 예약 작업을 정리한 뒤 음성 및 Gateway 연결을 종료한다.
  이전 관리자가 새 관리자의 명령에도 중복 응답하지 않도록 하기 위함이다.

접속·대기는 Discord의 관리자 또는 서버 관리 권한이 있는 사용자만 사용할 수 있다.
다른 서버의 명령은 처리하지 않는다. 음성채널이 없는 사용자에게 사용할 기본 채널은
현재 접속 채널과 별도로 보존한다. 설정 창에서 음성채널 ID를 저장하면 기본값을 변경한다.

## 재접속

GUI·봇이 공유하는 로컬 상태 파일로 전체 봇 재시작·GUI 프로세스 복구 시도를 최대 10회로 제한한다.
재시도 간격은 최소 5초이며 첫 수동 실행은 별도다. 음성 재연결도 별도 10회 제한과 권한 검사를 따른다.
2026-10-05부터 Gateway 통신 오류는 `discord.py`의 세션 재개·오류별 대기 처리를 먼저 사용한다.
최초 Gateway 연결부터 복구 감시를 시작하고, 90초 동안 정상 연결되지 않을 때 전체 봇을 재시작한다.
이 세션 재개 기간에는 라이브러리가 내부 재시도를 수행하므로 전체 재시작 횟수와 개별 통신 재시도 횟수는 다르다.
음성 연결은 라이브러리의 내부 자동 재연결 대신 기존 권한 검사를 거친 자체 복구를 유지한다.
10초간 권한 확인이 갱신되지 않으면 음성 송출을 중단하며 이 안전 조건은 늘리지 않는다.

살아 있는 봇이 음성 재접속을 시도할 때 GUI가 다시 프로세스를 재시작하지 않는다.
권한 오류(HTTP 403 / Discord 50001·50013)는 즉시 중단한다.
네트워크 시간 초과는 정해진 횟수 안에서 재시도한다.

10회 제한 뒤 Gateway가 연결되어 있다면 `/보탐 동작:접속`으로 다시 시도할 수 있다.
Gateway까지 끊겼거나 `/대기`한 경우에는 디코 명령을 받을 수 없다.
이때 프로그램의 봇 버튼으로 수동 실행한다. 대기 상태인 실행 중 프로세스는
버튼 클릭 시 정리한 뒤 다시 실행한다. 자동으로 대기를 해제하지 않는다.

상태는 봇 설정 파일 옆의 `.connection.json`에 원자적으로 저장한다.
서버별 설정 경로에 따라 분리되며 토큰·스케줄은 넣지 않는다.
프로세스 간 잠금으로 복구 횟수 덮어쓰기를 방지한다. 손상된 상태 파일은 자동 접속하지 않는다.

## 범위와 검증

프로그램의 봇 실행 버튼에는 GitHub 업로드 확인 → 기존 봇 종료 → 새 관리자
다운로드/적용과 접속 병행 → 모두 완료 후 송출 재개 절차를 연결했다.
양쪽 진행창과 편집 잠금, 실패 처리 및 최초 등록 조건은
[관리자 스케줄 승계](discord_handover.md)를 참고한다.
구버전 봇은 담당 기록에 나타나지 않으므로 최초 등록 전에 종료를 확인해야 한다.

GUI와 디스코드 봇 소스를 함께 갱신해야 한다. 빌드·ZIP·실제 Discord 접속은 하지 않았다.

비빌드 테스트: `python -B -m unittest test_discord_connection_control test_discord_server_isolation test_discord_voice_commands test_discord_notice_output test_discord_connection_visual test_voice_bridge_receipts`

테스트는 임시 설정과 가짜 Discord 이벤트를 사용하며 실제 사용자 설정이나 음성을 변경하지 않는다.
