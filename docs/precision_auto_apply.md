# 초정밀 측정창 클릭 / 자동적용

최근 로그의 반복 중단은 사용자 취소 이벤트가 아니라 `시간표 제목/지역이 변경됐습니다` 오류였다.
팝업 클릭에 따른 게임 비활성화/화면 변화 가능성을 줄이기 위해 측정창에 Windows
`WS_EX_NOACTIVATE`를 설정한다. 클릭을 통과시키는 스타일은 사용하지 않아 체크박스와
취소 버튼은 계속 조작할 수 있다. 제목/지역 변경 및 ROI 가림 검사는 그대로 유지한다.
Windows 동작 참고: [Microsoft 창 활성화 설명](https://devblogs.microsoft.com/oldnewthing/20240919-00/?p=110283).
실제 게임에서 클릭과 중단의 인과관계를 재현 검증한 것은 아니다.

## 시작 직후 중단 회귀 수정 (2026-09-28)

22:50 로그의 6회 시도 모두 0.36~0.39초 안에 제목/지역 변경 검사로 중단됐다.
측정창 생성 후 `deiconify()`가 생성자와 호출부에서 중복 호출되고 있었다.
Windows Tk의 `wm deiconify`는 NOACTIVATE 스타일과 별개로 명시적인 포커스
요청을 실행한다. `wm state normal`은 그 요청 없이 창을 표시한다.
[Tk Windows 구현](https://raw.githubusercontent.com/tcltk/tk/core-8-6-branch/win/tkWinWm.c)의
`TkpWinToplevelDeiconify`와 `WmStateCmd`에 이 차이가 명시되어 있다.

진행창은 `state('normal')`로 한 번만 표시하고 호출부의 `deiconify/lift`는 제거했다.
최초 캡처 후 즉시 표시, 게임 상단 배치, 자동적용/취소 버튼은 유지한다.
추적 시작을 늦추거나 제목/지역 가드의 기준·임계값을 바꾸지 않는다.
이 변경은 확인된 포커스 요청 경로를 수정한 것이며, 실제 게임의 화면 변화와
오탐이 사라지는지는 사용자 재측정으로 확인해야 한다.

- 기존 창 높이/게임 상단 배치를 유지하고 `n회/초` 아래 `자동적용`을 추가한다.
- 신규 설정/배포 기본값은 해제. 사용자의 선택은 `precision_auto_apply`로 INI에 보관한다.
- 정상 계측 결과를 소수점 그대로 텍스트에 반영한 후 측정창을 닫고 잠금을 해제한다.
- 300ms 후 동일 입력창·서버·텍스트이며 새 측정이 없을 때만 기존 `_apply_schedule_input_batch`를 한 번 호출한다.
- 자동적용에서는 `auto_confirm_update=True`로 기존 스케쥴 갱신 확인까지 승인한다.
  기존 `skip_overwrite_confirm` 경로로 연결하여 갱신 팝업에서 기다리지 않고 적용한다.
  중복 보스/불확실 입력 검사는 유지하며 수동 적용에서는 갱신 확인창도 그대로 표시한다.
- 취소/오류/확정 결과 없음/미확정 보스가 남은 경우 자동적용은 보류한다.
- 미확정 보스만 재시도하는 기존 확인창은 유지하며, 재시도가 모두 성공하면 자동적용 가능하다.
- 사용자가 취소한 경우 이미 도착한 완료 이벤트도 결과 반영/자동적용하지 않는다.

게임·실제 Tk 창을 조작하지 않은 모의 UI 테스트와 기존 추적 계산 테스트로 검증한다.
