## 원인과 수정

- 실제 저장 공지 `CT9G/1973`의 `클래스 변경권 판매 및 클래스 변경 기간`은 기존 구매/사용 키워드와 일치하지 않아 기간 후보가 0개였다.
- 공통 기간을 구매와 사용 두 사실로 분리한다. `점검 후`가 시작인 경우 명시된 종료 시각과 시작 조건/날짜를 각각 보존한다.
- 같은 날짜 정기점검 공지를 분석하여 시작을 연결한다. 목록 순서와 무관하게 같은 수집 회차의 본문을 함께 참조한다.
- 기존 점검 선택 규칙을 재사용한다: 완료/연장 우선순위, 충돌·오류·다른 날짜·미래 종료의 추측 금지. 별도 시각을 하드코딩하지 않는다.
- 점검 시작을 해소하지 못해도 종료는 보존한다. 그 경우 구매 시작 안내는 만들지 않고 명시된 종료에 기반한 마감 후보만 만든다. 알림의 유효 시작과 실제 행사 시작은 별도 필드이다.
- 제작 기간은 구매/사용 기간으로 사용하지 않는다. 미확정 이력만 남아 있는 정상 분석 공지에 미확정 안내 설명을 계속 붙이지 않는다.
