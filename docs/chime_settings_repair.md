# 차임벨 빈 값 승계 점검 (2026-09-29)

## 확인한 데이터

- 현재 선택: season_26 / 서버 9.
- 18시즌 설정과 롤백 원본은 일반/고정/연속 차임벨 3개가 정상이다.
- 19~26시즌 설정과 롤백 원본은 3개가 모두 빈 문자열이다. 새 시즌 설정 승계가 이를 복사해 왔다.
- AppData/init/default_schedule_alarm_settings.json도 3개가 비어 있다.
- 프로젝트의 배포 기본값 init/default_schedule_alarm_settings.json은 정상이며 음성 파일이 존재한다.
- 현재 26시즌의 고정보스 정의는 정상 18시즌 및 AppData 공용 정의와 해시가 같다. 고정보스 목록 자체가 삭제된 증거는 없다.

## 수정

- 일반 설정 저장 시 공용 기본값 파일을 갱신하던 호출을 제거했다. 기본값 승격은 명시적인 별도 작업으로만 한다.
- 비동기 저장 시작 시 경로와 저장 순번을 고정한다. 실행 도중 프로필이 바뀌어도 다른 서버에 쓰지 않으며 같은 프로필의 늦은 이전 저장도 최신 저장을 덮어쓰지 않는다.
- 파일은 임시 파일 후 원자적으로 교체한다. 차임벨 편집창에서 저장 실패를 성공으로 표시하지 않는다.
- 편집 중 서버/시즌이 바뀌면 저장을 막는다.
- 알람 파일이 없는 빈 프로필에서도 하드코딩된 빈 고정보스 override 대신 실제 배포 기본값을 먼저 읽는다. 사용자 명시적 빈 차임벨 선택은 자동으로 되살리지 않는다.

## 현재 파일 복구 절차

2026-10-01 추가 확인: 사용자가 현재 차임벨을 다시 지정했다. 빈 값 복구 스크립트는 실행하지 않았고, 현재 선택(일반 1 / 고정 2 / 연속 3)을 `promote_current_defaults.py`로 롤백·공용 기본값에 반영했다. 기존 파일은 별도 백업했다. 자세한 경로는 `notice_grouping_20261001.md`에 기록했다.

`repair_current_chimes.py`는 기본 실행 시 대상만 출력한다. 사용자가 프로그램을 종료한 뒤 `--apply`로 실행한다.

- 현재 프로필의 차임벨, 그 프로필의 롤백 차임벨, 공용 빈 차임벨 기본값만 대상으로 삼는다.
- 세 차임벨이 모두 빈 경우에만 배포 기본 선택을 넣는다. 다른 설정/스케줄/고정보스/토큰은 변경하지 않는다.
- 원본은 현재 프로필의 settings_rollback/before_chime_repair_날짜 폴더에 보관한다.
- 활성 프로필 및 원본 변경을 재확인한 뒤 저장한다. 이후 수정된 소스 또는 수동으로 새로 빌드한 버전으로 실행해야 한다.
- 실행 중인 이전 버전이 종료하면서 빈 메모리 설정을 다시 쓰지 않도록 종료 확인 전에 적용하지 않는다.
