# 배포 기본설정 덮어쓰기 선언

평소에는 기존 AppData 설정을 우선합니다. 배포자가 특정 항목의 덮어쓰기를 선언한 EXE만 예외적으로 첫 적용 시 AppData로 먼저 복사하고, 그다음 프로그램 설정과 보스 목록을 읽습니다. 소스 실행에서는 배포 선언을 소비하지 않습니다.

## 보스 스케줄의 배포설정

마스터 관리자에게만 **튜토리얼 왼쪽 → 배포설정** 버튼이 보입니다. Windows 관리자 권한이나 일반 운영 관리자라는 이유로 표시하지 않습니다. 창 열기와 저장에서도 마스터 여부를 재확인합니다. 기존 배너알림은 버튼 왼쪽으로 이동해 겹치지 않습니다.

빌드 원본 폴더(`boss_timer_gui.spec`가 있는 폴더)를 확인하고 파일별 체크박스를 선택한 뒤 **현재 설정으로 저장**을 누릅니다. 소스 실행에서는 현재 프로젝트를 자동 선택하며, EXE에서 준비할 때는 원본 폴더를 지정할 수 있습니다. 선택한 파일의 현재 저장값을 배포 원본으로 복사하고 `init/distribution_defaults.json`에 새 선언을 저장합니다. 실행 중인 AppData를 초기화하거나 빌드를 시작하지 않습니다.

현재 선택은 선언 파일에 저장되므로 창을 다시 열어도 유지됩니다. 전체 선택·전체 해제를 지원하며, 전부 해제 후 저장하면 다음 배포의 덮어쓰기를 끕니다. 폴더 위치는 해당 PC의 `distribution_settings_ui.json`에 기억합니다. 수정을 완료하지 않은 다른 설정창의 입력 중인 내용은 캡처하지 않습니다. 현재 설정 파일이 아직 없으면 기존 배포 원본을 유지합니다.

파일별 목록은 다음과 같습니다.

| 항목 / 선택 ID | 배포 설정 파일 |
| --- | --- |
| 일반 환경설정 `settings` | `init/default_settings.ini` — 기존 공개 설정 허용 목록 66개만 적용 |
| 보스 설정 `boss_definition` | `init/schedule_boss_definitions.txt` |
| 지역·챕터 `areas` | `init/schedule_area_definitions.txt` |
| 고정보스 `fixed` | `init/schedule_fixed_bosses.txt` |
| 보스 시간·점수 `metrics` | `init/schedule_boss_metrics.json` |
| 휴식 `breaks` | `init/schedule_break_rules.json` |
| 보스 알람 `alarm` | `init/default_schedule_alarm_settings.json` |
| 음성 합성 `voice` | `init/default_edge_tts.ini` |
| 알리미·안내 문구 `notice` | `init/default_notice_settings.json` |
| 알리미 실행 코드 · 이번 배포본 사용 `notice_module` | `init/default_notice_module.json` — 설치 모듈 우선 선택을 1회 해제 |
| 음악 검색 `music` | `init/default_background_music_settings.json` |
| 웹 스펙트럼 `spectrum` | `web_assets/boss_spectrum.json` |
| 웹 글꼴별 기본 크기 `font_sizes` | `web_assets/fonts/size_defaults.json` |

기존 보스·고정보스·스펙트럼 선언은 보스·지역·고정보스·스펙트럼 네 체크로 이어받습니다. 기존 `boss` 명령은 보스와 지역 파일을 함께 선택하는 호환 항목입니다. 보스·고정보스·휴식·시간/점수 선택은 관련 공통 표시 옵션도 함께 담습니다.

비밀번호, 토큰, 관리자·서버·시즌 식별값, 실제 스케줄, 개인 음성 파일 및 웹 사용자의 기기별 선택은 포함하지 않습니다. 알리미를 선택해도 공지·송출 장부는 유지하고 설정·문구만 바꿉니다. 웹 글꼴은 기본 크기만 바꾸고 개인 글꼴·비활성 목록·개인 선택을 보존합니다. 선택하지 않은 설정 원본과 현재 사용값은 유지합니다.

## 다음 배포를 준비할 때

배포설정 창에서 저장한 `init` 및 `web_assets`가 배포 원본입니다. 이전 배포 원본은 프로젝트의 `settings_seed_backups/distribution_ui_*`에 백업합니다. 고급 명령으로 선언만 준비하는 기존 경로도 계속 지원합니다.

상단의 **롤백값 갱신**은 현재 서버의 저장된 보스·지역·고정보스·소요시간/점수·휴식·알람·음성 설정을
새 시즌 시작 → 설정롤백의 **현재 기준점**으로 저장합니다. 알리미 설정 파일이 있으면 사용 설정과
안내 문구도 포함하며 공지·송출 이력은 제외합니다. 먼저 각 설정 창의 수정을 완료한 뒤 누릅니다.
기존 기준점은 같은 `settings_rollback` 폴더의 `before_refresh_*`에 보관합니다. 저장 실패 시 기존
기준점을 유지하며, 새 시즌은 갱신한 기준점을 이어받습니다. 실제 스케줄·접속 정보와 다른 서버는
변경하지 않습니다. 이 버튼은 현재 PC의 롤백 기준점 갱신이며 배포 체크 항목의 저장은 기존
**현재 설정으로 저장** 버튼에서 진행합니다.

```powershell
# 미리보기만 실행
python -B declare_distribution_defaults.py --groups boss fixed spectrum

# 선택한 항목의 덮어쓰기를 선언 파일에 저장. 빌드는 실행하지 않음.
python -B declare_distribution_defaults.py --groups boss fixed spectrum --apply

# 이후 일반 배포로 바꾸려면 선언 해제. 기존 AppData를 우선하게 됨.
python -B declare_distribution_defaults.py --clear --apply
```

대화에서 “이번 배포는 고정보스 기본값을 덮어써”처럼 대상 항목을 지정해도 같은 선언 파일을 준비할 수 있습니다. 선언 후 해당 기본설정을 다시 수정했다면 재선언합니다. 선언과 파일 내용이 다르면 빌드 시작 전에 오류로 알려줍니다. 동일 EXE 버전으로 다시 배포하더라도 새 선언은 별도 차수로 구분합니다. 선언하지 않은 상태의 단순 재빌드는 기존 사용자 설정을 덮지 않습니다.

빌드·복사·배포는 사용자가 수동으로 진행합니다. 선언한 설정은 빌드 PC의 다른 AppData 값으로 교체하지 않고 고정된 원본을 포함합니다. 알리미 기본 문구는 내장 알리미 모듈에도 동일하게 포함합니다.

## 수신 PC의 처리

1. 기존 데이터 이관과 현재 서버·시즌 식별 후, 선언 대상 설정을 읽기 전에 적용합니다.
2. 적용 전 파일은 `AppData\Roaming\BossTimer\distribution_defaults\backups\<선언 ID>_<백업 ID>`에 보관합니다. 기존 파일 유무와 원본 경로도 백업 목록에 기록합니다.
3. 공통 기본 파일과 현재 서버 프로필의 선언 대상 파일을 반영합니다. 이미 존재하는 새 시즌 메뉴의 롤백 기준점도 해당 파일만 갱신하며 같은 분류의 선택하지 않은 다른 파일은 유지합니다.
4. 전부 저장·검증된 후 항목별 적용 차수를 기록합니다. 같은 선언을 재실행해도 다시 덮지 않으므로 사용자가 이후 수정한 설정은 유지합니다.
5. 이후 다른 서버 프로필을 처음 열면 그 프로필에도 선언 항목을 한 번 적용합니다. 다른 서버를 열었다는 이유로 공통 설정을 재설정하지는 않습니다. 더 오래된 선언을 가진 EXE는 이미 최신 선언이 적용된 항목을 되돌리지 않습니다.

복사 실패 시 이번 적용에서 변경한 파일을 원래 값으로 되돌리고 성공 기록을 남기지 않습니다. 설정을 혼합한 채 시작하지 않고 부모 창 중앙 오류 안내 후 실행을 중단합니다. 재실행 시 미완료 선언을 다시 시도합니다. 성공 경로에는 확인창이 없습니다.

적용 기록: `AppData\Roaming\BossTimer\distribution_defaults\applied.json`. 이 기록과 백업은 수신 PC 소유이며 배포에 포함하지 않습니다.

검증: `test_distribution_selection.py`, `test_distribution_defaults.py`, 기존 저장소·프로필 전환·새 시즌·스펙트럼·배포 사전검사. 단위 검증의 설정 파일 생성은 OS 임시 폴더에서만 수행하며 실제 EXE·ZIP 빌드는 실행하지 않습니다.


## 알리미 코드와 클라이언트 설정 구분

안내 유형 목록·참여 독려 판정·Discord 채팅 전달은 알리미 실행 코드입니다. 서버별 수집/송출 사용,
유형별 사용 체크, 직접 고친 문구와 공지·완료 장부는 AppData의 `notice_data/<서버 해시>.json`에
독립적으로 저장합니다. 기존 서버 파일이 있으면 이 개인 설정을 읽으며 배포 기본값을 매번 덮지 않습니다.

별도로 설치한 알리미는 `update_ai/versions`와 `update_ai/state.json`에서 선택합니다. 내장 버전보다
높은 설치 버전은 새 GUI/봇을 배포해도 우선 실행될 수 있습니다. 이번 GUI의 안내 코드가 필요하면
배포설정에서 **알리미 실행 코드 · 이번 배포본 사용**을 체크하고 저장합니다. 받는 PC는 원래 상태를
백업하고 active/pending/previous 선택만 1회 해제하여 내장 코드를 시작합니다. 설치 파일·업데이트
사용 설정·개인 문구·유형 체크·공지·송출 이력은 지우지 않습니다. 이후 사용자가 별도 모듈을
설치하면 평소대로 적용되며 같은 배포 선언이 다시 초기화하지 않습니다.

개인 사용 설정/문구까지 배포자의 값으로 맞추려면 기존 **알리미 설정 / 안내 문구**도 선택합니다.
두 항목은 독립적이며 등록된 공지를 강제로 다시 보내거나 이미 완료한 안내를 초기화하지 않습니다.
시작 진단 `notice_module_started`에는 version과 source(bundled/installed)를 함께 남깁니다.
참여 독려는 상시 안내가 아니므로 정해진 시각·대상 보스·1분 전 안내 완료 등 송출 조건도 확인해야 합니다.
