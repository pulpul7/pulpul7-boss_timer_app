# 봇 연결과 관리자 송출 권한

프로그램 시작 시 저장된 Discord 필수 설정이 완성되어 있으면 봇 Gateway만 연결한다.
음성채널 입장과 송출 권한은 프로그램 버튼 또는 관리자 명령으로 별도 요청한다.
설정, 스케줄, 차임벨, 음성 파일을 초기화하지 않는다.
GUI와 봇 모두 이번 소스로 교체해야 하며, 빌드와 실제 검증은 사용자가 진행한다.

## 버튼과 표시

- 디코 실행: 연결된 봇을 재사용하고, 연결이 끊겼으면 재연결한다.
- 현재 담당자가 없으면 권한을 얻고 저장된 음성채널로 입장한다.
- 다른 담당자가 있으면 부모 중앙 자체 팝업으로 승계를 묻는다. 아니오는 봇 연결만 유지한다.
- 디코 종료: 현재 담당자의 음성 연결과 권한만 종료한다. Gateway는 유지한다.
- 화면은 봇 연결됨·권한 없음 / 관리자·입장 중 / 관리자·송출 중 / 봇 연결 끊김을 구분한다.

## 관리자 명령

Discord의 서버 관리자 또는 서버 관리 권한이 필요하다. 슬래시 명령에서 동작 입력란에 값을 넣는다.

- `/보탐 관리자`: 접속한 담당자의 이름, 설치별 ID, 게임 서버·시즌, 권한 상태를 표시한다.
- `/보탐 나츠`: 목록에 표시된 담당자 이름으로 해당 PC를 호출한다. 봇만 연결되고 권한이 없어도 처리한다.
- 같은 이름이 여러 명이면 호출을 중단하고 ID로 구분하도록 안내한다. `/보탐 a1b2c3d4` 또는 기존 `/보탐 관리자 a1b2c3d4`, `/보탐 관리자a1b2c3d4`도 허용한다.
- ID는 기본 8자리이며 충돌하면 길게 표시한다. 이름이나 시즌 변경으로 ID가 바뀌지 않는다.
- 원격 호출은 추가 확인 없이 승계한다. 호출자의 음성채널이 우선이며, 없으면 대상 PC의 저장된 채널을 사용한다.
- 대상 PC가 10초 안에 요청을 수락하지 않으면 기존 담당자의 권한을 변경하지 않는다.
- 같은 명령을 여러 PC가 수신해도 최초 Discord 응답에 성공한 PC만 처리한다.
- `/보탐 접속`, `/초대`, `/대기`는 현재 담당자의 접속·권한 반납 경로를 이용한다.

## 송출 권한 없는 조회

봇 Gateway만 연결돼 있어도 `/보탐`, `/보탐 ?`, `/보탐텍스트`, `/이미지`, `/음성`, `/음성목록`에 응답한다.
권한이 없는 PC는 요청자만 볼 수 있는 응답으로 자신의 로컬 자료를 제공하고 응답 PC의 관리자 ID를 표시한다.
조회는 송출 중인 담당자를 우선하고, 나머지는 실제 봇 접속 시각이 최근인 순서로 요청한다. 주기적인 상태 갱신은 접속 순서를 바꾸지 않는다.
담당자 목록과 유지 중인 조회 담당자는 기존 5초 권한 확인 때 로컬 연결 상태에 저장한다. 정상 조회는 이 정보로 응답 PC를 선택하며 GitHub 읽기·쓰기나 GUI 요청 처리를 기다리지 않는다.
송출 중인 PC는 대기 없이 접수하고 바로 자신의 스케줄을 응답한다. 권한이 없는 조회 담당자는 짧게 송출 담당자에게 우선 기회를 주고 접수한다.
나머지 PC는 Discord의 접수·응답 상태를 확인하여 중복 처리를 종료한다. 조회 담당자가 응답하지 않거나 캐시가 만료됐을 때만 공유 기록의 SHA 비교로 재시도한다.
`/보탐 관리자`도 유효한 로컬 목록이 있으면 바로 응답하며, 없을 때 기존 조회 경로를 사용한다. Discord 서버 관리 권한 검사는 유지한다.
선택한 PC의 처리 준비 응답이 3초 안에 없으면 다음 PC로 바꾸고, 이전·새 담당자 이름과 재시도 안내를 요청자에게 표시한다.
모든 후보가 응답하지 않으면 관리자를 변경하고 다시 시도하도록 안내한다. 이는 조회 담당자 선택이며 음성 송출 권한 승계가 아니다.
재시도로 바뀐 조회 담당자는 이후 명령에서도 유지한다. 새 PC가 접속해도 유지하며, 송출 중인 담당자가 있으면 그 담당자를 최우선으로 한다.
변경된 조회 담당자가 목록에서 빠지거나 실행 세션이 바뀌면 유지 기록을 해제하고, 남은 PC 중 가장 최근 봇 접속자부터 다시 선택한다.
동시에 진행된 이전 조회가 나중에 끝나도 새 조회 담당자 유지 기록을 덮어쓰지 못하도록 별도 세대를 확인한다.
이미지 생성처럼 오래 걸리는 작업은 처리 준비 응답 후 진행한다. 3초는 최종 이미지 생성 완료 제한이 아니다.
정상 조회는 최초 Discord 접수에 성공한 PC만 처리한다. 재시도 경로는 실행 세션·요청 번호·후보 순서·응답 기한을 비교해 늦은 PC의 중복 응답을 막는다.
도움말은 항상 개인 응답이며, 현재 담당자의 스케줄 채널 전송·음성 버튼 동작은 유지한다.
권한 없는 음성 목록은 이름만 표시하며 재생 버튼을 제공하지 않는다.
이미지 생성은 기존 로컬 스케쥴복사 경로를 이용하므로 클립보드도 기존과 같이 갱신된다.
권한 없는 조회는 권한 획득·스케줄 변경·공용 채널 안내·메시지 정리·자동 송출을 수행하지 않는다.
관리자 명령의 Discord 서버 관리 권한 검사와 스케줄 변경·음성 송출의 담당자 검사는 유지한다.

## 승계와 스케줄

권한은 Discord 서버마다 한 명이며 게임 서버·시즌 일치 여부는 승계를 막지 않는다.
기존 담당자는 송출을 중단하고 스케줄 스냅샷을 업로드한다. 업로드 성공·실패는 승계를 막지 않는다.
기존 담당자의 응답·업로드를 최대 10초 기다린 뒤 새 담당자에게 권한을 넘긴다.
새 담당자는 자신의 로컬 스케줄을 사용하며 다운로드·적용·자동 동기화를 하지 않는다.
음성 입장은 별도로 최대 30초 확인한다. 실패하면 봇 연결을 유지하고 권한만 반납한다.
이전 담당자는 자동 복귀하지 않는다. 스케줄 가져오기와 동기화는 사용자가 기존 메뉴로 진행한다.
기존의 일반 시작 시 누락 프로필을 채우는 동작은 승계와 별개이며 이번 변경 대상이 아니다.

## 저장소·세션

기존 GitHub 데이터 저장소의 `data/handover/<Discord 서버 ID 해시>.json`을 사용한다.
Contents 쓰기 권한이 필요하다. 새 저장소나 별도 서버를 만들지 않는다.
조회 조정은 같은 저장소의 `data/handover/<Discord 서버 ID 해시>_queries.json`을 사용하며 권한 기록과 분리한다.
정상 조회에는 조회 조정 파일을 읽거나 쓰지 않는다. 재시도로 조회 담당자가 바뀔 때만 권한 기록에 조회 담당자 정보·별도 세대를 함께 공유하며, 시작 시 기존 조회 담당자 기록을 한 번 반영한다.
조회 기록에는 요청 번호·담당자 표시 정보·실행 세션·후보 순서·유지할 조회 담당자와 변경 세대를 저장한다. Discord interaction 토큰·스케줄·음성 데이터는 업로드하지 않는다.
조회 기록은 최대 32개이며 120초 지난 기록은 다음 조회 생성 때 정리한다.
프로토콜 2 기록에는 설치 ID, 실행 세션, 권한 세대, 요청, 담당자 표시 정보와 접속 상태가 들어간다.
토큰·Windows 사용자 이름·PC 이름은 공유하지 않는다.
SHA 비교 변경으로 동시에 요청된 승계를 직렬화하며, 오래된 작업은 새 권한 기록을 덮어쓰지 못한다.
접속 정보는 20초마다 갱신하고 60초 동안 갱신되지 않은 담당자는 목록에서 제외한다.
권한은 5초마다 확인한다. 마지막 확인 후 10초가 지나면 음성 패킷·채팅 송출을 차단한다.
권한 저장소 장애는 봇 로그인을 종료하지 않지만 권한 취득·갱신은 막는다.
음성 재시도와 Gateway 재시도는 별도 10회 제한으로 관리한다.
권한 상태 파일은 Windows에서 읽는 동안에도 원자적 교체를 허용한다. 일시적인 상태 포트 무응답은 기존 권한 유효기간 안에서 기다린다.
음성 연결의 시간 초과·취소 때 연결 객체와 등록 정보를 정리한다. 음성 재시도 한도에 도달하면 오류를 표시하고 권한을 반납하며 Gateway는 유지한다.
기존 프로세스는 관리자 ID·설정 경로·Application ID·Discord 서버·프로토콜이 일치할 때만 재사용한다.
구버전 연결이 모두 종료된 뒤, 남은 구버전 담당 기록은 디코 실행 버튼의 첫 확인으로 전환한다.
담당자 ID 파일을 다른 PC에 복사하지 않는다. 서로 다른 PC는 각자 고유한 ID를 사용한다.

## 사용자 수동 확인

1. 시작 직후 음성 입장 없이 봇만 연결되는지 확인한다.
2. 담당자 없음, 승계 예·아니오, 권한 반납, 연결 끊김 후 재연결을 확인한다.
3. 업로드 실패·지연, 기존 담당자 무응답에도 새 담당자가 입장하며 양쪽 Gateway가 유지되는지 확인한다.
4. 새 담당자의 로컬 스케줄·음성 설정이 변하지 않는지, 음성 입장 실패 시 권한만 반납하는지 확인한다.
5. 담당자가 없을 때 관리자 목록, `/보탐 나츠` 이름 호출·중복 이름 안내·ID 호출, 호출자 채널 우선·대상 기본 채널을 확인한다.
6. 일반 사용자의 관리자 명령 거절, 동시 요청과 명령 중복 응답 방지를 확인한다.
7. 권한 저장소 연결을 끊었을 때 10초 뒤 송출이 중단되고, 복구 시 현재 담당자만 재접속하는지 확인한다.
8. 이전 PC의 늦은 종료·재연결이 새 담당자의 음성 세션을 끊지 않는지 확인한다.
9. 음성 연결이 시간 초과되거나 취소된 뒤 다시 실행할 때 `Already connected to a voice channel`이 반복되지 않는지, 재시도 한도 후 오류 표시와 권한 반납을 확인한다.
10. 조회가 송출 중인 PC를 우선하는지, 모두 권한이 없으면 마지막 봇 접속 PC를 선택하는지 확인한다. 상태 갱신만으로 순서가 바뀌지 않아야 한다.
11. 첫 조회 담당자가 무응답일 때 3초 응답 기한 후 다음 담당자로 재요청하고 안내하는지, 모든 후보가 실패하면 관리자 변경·재시도 안내가 나오는지 확인한다.
12. 재시도 뒤 이전 PC의 늦은 응답이 중복 표시되지 않는지, 조회 담당자 변경으로 송출 권한이나 로컬 스케줄이 바뀌지 않는지 확인한다.
13. 재시도로 변경된 조회 담당자가 다음 명령에도 유지되는지, 송출 중인 담당자가 있으면 우선하는지, 유지 중인 PC가 끊기면 다시 선택하는지 확인한다.
14. 정상 `/보탐`·`/보탐텍스트`·`/음성목록` 조회 때 로그에 `query_direct`가 나오고 관리자 요청 파일이나 GitHub 조회 조정 쓰기가 생기지 않는지 확인한다.
