# 관리자 스케줄 승계

봇 실행 버튼은 먼저 기존 GitHub 데이터 저장소의 서버별 담당 기록을 확인한다.
별도 저장소나 토큰을 하드코딩하지 않고 현재 서버 업로드의 owner/repo/branch/token을 사용한다.
양쪽 모두 이번 GUI·봇 소스와 데이터 저장소 Contents 쓰기 권한이 필요하다.

## 절차

1. 새 관리자에게 부모 중앙 진행창을 표시하고 편집과 송출을 잠근다.
2. 서버·시즌이 같은 기존 담당자에게 요청 번호를 가진 인계를 요청한다.
3. 기존 관리자는 약 5초 주기로 요청을 확인한다. 진행창과 편집·송출 잠금을 적용한다.
4. 서버 업로드 버튼의 `_upload_current_schedule_to_github_data` 경로로 업로드한다.
   `True` 반환만으로 성공 처리하지 않는다. 실제 원격 내용과 현재 스케줄의 해시가 같고,
   업로드 도중 자료가 바뀌지 않았는지 확인한다. 서버의 더 최신 버전 때문에 업로드가
   생략되었고 내용이 다르면 인계를 중단하며 기존 관리자가 운영을 유지한다.
5. 업로드 파일 경로·Git SHA·데이터 버전·내용 해시를 공유하고 기존 봇을 종료한다.
   종료 확인 전에는 새 관리자의 접속을 허용하지 않는다.
6. 새 관리자가 Discord 접속과 정확히 해당 파일의 다운로드/검증/적용을 병행한다.
   기존 로컬 자료는 기존 가져오기 경로로 백업한다. 초·소수점 값을 텍스트로 재파싱하지 않는다.
7. 한쪽만 끝나도 진행창은 유지한다. 양쪽 작업이 모두 성공하고 담당자 기록 변경이
   완료된 뒤에만 새 관리자의 송출 잠금을 푼다. 기존 관리자는 대기를 유지한다.

## 진행창·안전장치

- Tk 이벤트 루프는 계속 실행한다. 프로그램 내 다른 창의 입력을 grab으로 잠그고,
  메인/스케줄 창 종료·서버 전환·별도 동기화·디스코드 편집 요청도 차단한다.
- 동기화, 접속의 상태 및 경과 시간을 별도로 표시한다. 기본 제한시간은 180초다.
  네트워크 요청 자체의 종료 제한도 적용된다. 실패한 경우 잠금을 풀고 자체 오류창을 표시한다.
- 새 관리자의 실패 시 음성은 잠근 채 봇을 중단한다. 기존 봇이 이미 종료됐다면
  자동으로 되살리지 않는다. 의도한 수신 관리자가 다시 실행하면 확인된 인계 파일로 재시도한다.
- 기존 봇의 종료가 확인되지 않은 실패는 `released`로 기록하지 않는다.
- 상태 JSON은 `data/handover/<Discord 서버 ID 해시>.json`에 저장한다. 무작위 설치 ID,
  서버/시즌/요청 번호/단계/파일 식별값만 담으며 토큰과 PC 이름은 담지 않는다.
- 기존 GitHub 파일 SHA를 조건으로 변경하여 동시 요청과 오래된 완료 신호를 차단한다.
- 로컬 `.connection.json`의 `handover_hold`는 GUI·별도 스케줄러·봇이 함께 읽는다.
  기존 음성 작업을 정리하고, 동기화 중 쌓이는 봇 음성 요청은 재생하지 않고 버린다.
- 인계 업로드는 기존 버튼과 동일하게 보스설정도 업로드할 수 있으나, 이번 승계 적용은
  스케줄 데이터만 대상이다. 수신 PC의 봇 토큰·음성 설정·보스설정을 일괄 덮어쓰지 않는다.

## 운영 주의

최초 담당 기록이 없으면 구버전 봇이 실행 중인지 자동 확인할 수 없어 다른 PC의 봇을
종료했는지 한 번 확인한다. 구버전 관리자와 혼용하지 않는다.
앱 시작 때 다른 PC의 봇을 끊을 수 있던 무조건적인 원격 세션 정리 로그인은 제거했다.

기존 관리자가 꺼졌거나 통신하지 못하면 최신 자료를 요청할 수 없다. 제한시간 이후
중단하며, 오래된 GitHub 자료로 조용히 강제 승계하지 않는다. 네트워크 분리 상황의
강제 인계 및 자동 임대 만료는 이번 단계에 넣지 않았다.
일반 봇 종료 버튼으로 종료하면 담당 기록도 해제한다. 비정상 종료의 오래된 담당 기록은
기존 PC가 다시 실행하여 확인하거나 별도 복구 절차가 필요하다.

구현·검증은 소스 및 오프라인 모의 환경에서만 수행했다. 실제 GitHub 업로드,
Discord 로그인/송출, 배포 EXE/ZIP 생성은 수행하지 않았다.

테스트: `python -B -m unittest test_discord_handover test_discord_connection_control test_discord_server_isolation`
