# 배너알림

스케줄 우측 하단의 `튜토리얼` 왼쪽에 있는 `배너알림`을 켜면 화면 오른쪽 아래에
보스타이머 전용 배너를 표시합니다. 체크 상태는 기존 사용자 설정에 저장됩니다.
처음에는 꺼져 있으며, 켤 때 확인용 배너를 한 번 표시합니다.

- 봇이 연결되어 있으면 송출 권한 없이도 해당 PC에서 받을 수 있습니다.
- 설정된 안내채팅의 보탐매니저 새 메시지와 내용이 바뀐 메시지를 받습니다.
  5분 전, 1분 전, 젠, 알리미, 관리자 접속, 재입장 안내 등이 포함됩니다.
- 같은 보스의 이전 안내가 함께 들어 있는 젠 메시지는 최신 안내만 표시합니다.
- 긴 내용은 제목 70자, 본문 180자로 줄입니다. 원문은 Discord에서 확인합니다.
- 내부 승계 스레드, 사용자 채팅, 개인용 명령 응답은 배너 대상이 아닙니다.
- 배너 자체의 알림음은 사용하지 않습니다. 기존 음성 설정은 그대로 유지합니다.

짙은 남색 카드가 약 0.45초 동안 부드럽게 올라오고, 10초 유지한 뒤 서서히 사라집니다.
남은 표시 시간은 아래쪽 가느다란 선으로 표시합니다. 최대 3개를 함께 표시하고
새 배너는 기존 배너 위에 쌓입니다. 아래 배너가 사라져도 나머지 배너의 위치는
유지합니다. 위쪽 표시 공간이 없으면 기다렸다가 순서대로 표시합니다.
30초 이상 지난 대기 알림은 표시하지 않습니다.
닫기 버튼으로 일찍 닫을 수 있으며, 작업 중인 게임이나 창의 포커스를 가져오지 않습니다.
보스 이름은 Discord 안내의 ANSI 색상을 반영합니다. 5분 전은 노란색, 1분 전은
붉은색, 젠·타임은 초록색으로 강조합니다. 긴 내용은 화면에서 최대 3줄로 줄입니다.

자체 배너는 Discord 및 Windows의 기본 배너 설정과 별도로 그리는 프로그램 창입니다.
Windows 알림센터에도 기록을 보내되, 기본 Windows 팝업은 `SuppressPopup`으로
억제해 배너가 두 개 겹쳐 나오지 않도록 합니다.
[Microsoft API 설명](https://learn.microsoft.com/en-us/uwp/api/windows.ui.notifications.toastnotification.suppresspopup?view=winrt-26100)
알림센터 기록에는 Windows의 알림 허용 설정이 필요합니다. 기록 저장이 실패해도
자체 배너는 계속 표시합니다. 자체 배너를 그리지 못할 때는 Windows 기본 배너로
전환합니다. 배너 클릭으로 새 프로그램을 실행하는 동작은 없습니다.

배너를 켜거나 켜진 상태로 프로그램을 시작하면, 메인 화면이 준비된 뒤 숨겨진
배너 창 3개와 글꼴·그리기 요소를 나누어 준비합니다. 다음 알림에서는 같은 창을
재사용합니다. 껐다 켜도 캐시를 재사용하며 프로그램 종료 시 정리합니다.
꺼진 상태에서는 배너 창과 글꼴을 만들지 않습니다.

추가 설치 패키지는 없습니다. Windows 기본 PowerShell과 WinRT 알림 API를
배경 스레드에서 사용합니다. 안내 텍스트는 JSON 표준 입력으로 전달하고 XML
텍스트 노드에 넣으므로 셸 명령이나 XML 코드로 해석되지 않습니다.

소스는 역할에 따라 분리했습니다.

- `desktop_banner.py`: 봇 안내 정리·색상 데이터·로컬 전달·Windows 알림센터 작업.
- `desktop_banner_ui.py`: 배너 디자인·창 캐시·배치·애니메이션. Discord/음성 의존성 없음.
- `desktop_banner_service.py`: 수신 및 켜기/끄기·사전 준비·종료 관리.

메인 GUI는 설정 변경만 서비스에 전달하고 봇은 안내 데이터만 전달합니다.
애니메이션은 Tk의 예약 콜백을 사용하며 대기나 별도 배너 프로세스를 추가하지 않습니다.

봇의 Gateway 이벤트를 사용해 전달하므로 채팅 기록 조회나 Discord API 요청은
추가하지 않습니다. GUI와 봇 모두 새 소스를 반영해야 합니다. 실제 실행과 배포
빌드는 사용자 검증 대상입니다.
