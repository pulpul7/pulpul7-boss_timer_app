# 담당자 식별

- 저장: `%APPDATA%/BossTimer/administrator_identity.json`.
- `client_id`: 최초 한 번 생성하는 UUID(32자리). 실제 인계 비교에 사용하는 값이다.
- `name`: 시즌 입력창에서 받는 담당자 이름(1~40자). 다음 시즌에도 자동 입력된다.
- `identifier`: `담당자이름_전체고유ID`. 이름 변경 시 표시값만 갱신한다.
- `guild_name`: 이름을 등록/저장할 때의 길드명. 신원이나 소유권 판정에는 사용하지 않는다.
- 화면에는 고유 ID 앞 8자리만 표시하며 비교에는 항상 전체 ID를 쓴다.

현재 활성 프로필의 `discord_bot.ini.connection.json`에 ID가 있으면 공통 파일 최초 생성 때
그 값을 그대로 가져온다. 공통 파일이 생긴 후에는 어느 시즌/서버에서도 그것이 우선이다.
재접속 횟수·대기 상태 등 연결 정책은 기존처럼 프로필별로 남겨둔다.
서버/시즌 불일치 차단과 접속·동기화 완료 전 송출 금지는 변경하지 않는다.

기존 시즌 사용자는 실행 시 별도 담당자 이름 창을 한 번 표시한다. 시즌 재시작이나 스케줄
초기화는 하지 않는다. 나중에 등록을 선택하면 로컬 자료는 유지되지만 수동 봇 접속 전에 다시 묻는다.
새 시즌에서는 담당자 이름을 필수로 받으며 취소 시 이름/시즌 정보를 저장하지 않는다.
창을 여는 과정에서 최초 ID만 발급/이관될 수 있으나 이름을 취소해도 ID를 재발급하지 않는다.

이름·PC 이름·길드명을 GitHub 인계 기록에 새로 공개하지 않는다. 기존처럼 무작위 ID만 전송한다.
식별 파일은 배포·시즌 스케줄 동기화·설정 롤백에 넣지 않는다. 손상된 파일을 읽으면
새 ID를 조용히 발급하지 않고 오류를 표시하여 기존 담당 기록과 단절되는 것을 방지한다.

다른 PC는 별도 ID를 발급한다. AppData 전체를 다른 PC로 복제하면 이 ID도 복제되므로
PC 간 설정 복사 때는 `administrator_identity.json`과 구형 연결 상태 파일을 복사하지 않는다.
이 ID는 사용자 인증 수단이 아니라 프로그램 설치 식별값이다.

실제 GUI·봇 접속 테스트/빌드는 수행하지 않으며, 임시 파일과 모의 인계로 검증한다.
